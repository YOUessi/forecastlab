## 一、背景与要研究的问题

### 1.0 背景：被评测的是什么

ForecastLab 是一条"证据优先"的二元事件预测流水线，一次运行分六个阶段：

```text
① 规范化问题、生成检索词
② 整理证据，产出带逐字引用的"发现"
③ 构建世界状态（主体、假设、可见证据）
④ 主体行动推演（两轮：各主体行动 → 环境统一推进）
⑤ 审查：找漏洞、判断依据是否充分、决定最终概率的"依据"
⑥ 报告：给出是/否主观概率
```

评测方式是：准备一批**结果已经确定**的二元问题，让系统站在该问题的**信息截止日**（`as_of`）
"只看当天及之前的资料"给出概率，再与真实结果比对，用 Brier 分数和覆盖率衡量。

评测臂有三个：`full`（完整六阶段）、`single_agent`（问题 + 同一份证据，一次调用出概率）、
`no_evidence`（只给问题，不给任何证据，作为"模型自身知识"的对照）。

### 1.1 为什么要用"训练数据截止之后"的案例

本项目所用模型（`deepseek-flash` / DeepSeek-V4.1-Flash）的训练数据截止约 2025-05。如果评测题的结果
发生在截止日之前，模型可能"背出"答案，那么"给证据"和"不给证据"就没有区别，测不出系统的价值。

因此 v2 起所有案例的 `as_of` 都 ≥ 2025-07-01，事件确实落在模型知识之外。
v1 就是因为多数案例早于截止而存在泄漏，只作为早期基线保留。

### 1.2 四个待研究的问题

#### 问题 1：把证据包做厚，预测会更准吗？

- **现象**：v2 的证据包平均只有 2–3 条来源，且多为媒体标题级摘要；审查阶段经常抱怨
  "只有标题级摘要""缺少截至日可查的某类资料"。
- **假设**：来源更多、更权威、并补上"截至日当天可查的状态证据"，模型应该判断得更准。
- **检验方式**：固定温度下，同一批 20 题分别用**薄包**（v2，46 条证据）与**厚包**（本实验，67 条）
  跑 `single_agent` 臂；`no_evidence` 臂不读证据，作为噪声下限的对照。
- **实测结果**：厚包**没有更好，反而略差**（0.1217 vs 0.1130），而对照组两轮只漂移 0.002。
  加厚唯一确凿的作用是修掉了 `PN6` 的证据冲突（三条来源对"谁淘汰皇家马德里"说法不一致）。

#### 问题 2：让最终概率使用"世界建模 + 主体推演"，会比"仅证据"更准吗？

- **背景**：第 ⑤ 步（审查）决定第 ⑥ 步的概率依据。判为 `evidence_only` 时，报告拿到的输入里
  **世界状态和主体推演被清空**，并被明确要求"忽略世界建模与推演"；只有判为 `full` 才允许引用。
  也就是说，如果最终概率永远走 `evidence_only`，第 ③④ 两阶段的产出等于白算。
- **假设**：完整的建模与推演会提供"仅看证据"得不到的信息，因此应当更准。
- **检验方式**：**影子预测**——在同一个 run 内并联一次全依据的预测（同一问题、同一份证据，
  但把 world / simulation / 审查意见完整交给它），只记录不参与评分，形成成对比较（见 §六）。
- **实测结果**：两者**持平**（仅证据 0.1143 vs 含建模 0.1181，胜负 4:5）。
  在闸门被打开、15/20 案例真正以全依据出概率之后（v4-B），`full` 与 `single_agent` 仍然持平
  （0.148 vs 0.122）——**不是"通道没打开所以看不出"**。

#### 问题 3：流水线为什么几乎从不走"全依据"？闸门该不该放开？

- **现象**：v2 的 20 例里 **0 例**以 `full` 依据出概率；15 例走 `evidence_only`、5 例直接弃权。
  完整流水线给出的数字，实际全部来自"只看证据"的路径。
- **当时的猜测**：审查规则里有一条"只要 `unsupported_claims` 非空就判 blocked"，
  而预测类问题天生无法在截止日举证，所以这条规则过于激进——它挡死了全依据通道。
- **检验方式**：三轮对照——A（原样）、C（只放宽 `unsupported_claims` 一条）、
  B（再移除 `world.summary` 的 future_gap 检测、以及 `future_gap` 单独触发复审）。
- **实测结果**：**猜测错误**。C 与 A 的闸门分布完全相同（都是 `full` 0 例），说明
  `unsupported_claims` 从来不是实际约束；真正的闸门是 `future_gap` → `evidence_only`
  （世界状态摘要只要提到尚未发生的事件，就会被判定为"审查在索要未来证据"）。
  移除它（B 轮）能把"以全依据出概率"从 0 提到 15 例，但精度几乎不变。
- **附带结论**：该兜底行为被 `backend/tests/test_backtest.py` 的两个用例直接断言，
  属于**有意设计**而非缺陷，因此实验后已回退，未当 bug 修改。

#### 问题 4：运行方差有多大？会不会掩盖前三个答案？

- **现象**：同一个问题、同一份证据、同一份代码，两次运行 `no_evidence` 对 `PN3`
  分别给出 **0.90** 与 **0.05**，对 `PW1` 给出 0.14 与 0.35。
- **假设**：这是采样随机性（服务端默认 `temperature`），不是代码缺陷。
- **检验方式**：固定 `temperature=0` 后做小样重复，并横向对比各轮同一臂的得分；
  最后移除该参数再跑一轮（v5），核对结论是否依赖它。
- **实测结果**：固定温度把个案漂移从 ±0.48 量级压到 ±0.03 量级，但**没有消除**；
  `no_evidence` 臂在各轮之间仍浮动于 0.133–0.207。
  **由此确立一条纪律：小于约 0.04 的差异不可解读。** 问题 1 的"改善"正是因此被推翻。

## 五、三条核心结论

1. **加厚证据没有可测收益。** 固定温度下的干净对照中，厚包反而略差（0.1217 vs 0.1130），
   而对照组仅漂移 0.002。v3 曾观察到的 0.162 → 0.124"改善"确认为采样噪声。
   加厚唯一确凿的作用是修掉了 `PN6` 的证据冲突（三条来源对"谁淘汰皇家马德里"说法不一致）。
2. **全依据不比仅证据更准。** 两条独立证据：影子成对比较（0.1181 vs 0.1143）；
   闸门真正打开后（15/20 走全依据）full 0.148 vs single 0.122 仍持平。
3. **闸门是设计契约，不是缺陷。** ② 对闸门分布毫无影响；真正把全依据通道关死的是
   `future_gap` → `evidence_only`，而 `backend/tests/test_backtest.py` 有两个用例直接断言该行为，
   故 ①③ 已回退，未当 bug 修改。

此外，**方差主导**：`temperature=0` 能明显改善（抽样 3 例中 5/6 完全一致）但无法消除，
`no_evidence` 臂在各轮之间 Brier 浮动于 0.133–0.207。小于约 0.04 的差异不可解读——
结论 1 正是因此被推翻的。

## 六、关键概念

**全依据 vs 仅证据**：第 ⑤ 步（审查）决定第 ⑥ 步（报告）的概率依据。判为 `evidence_only` 时，
报告拿到的输入里世界状态与主体推演被清空，并被要求忽略它们；只有判为 `full` 时才允许引用。

**影子预测**：当依据被判为 `evidence_only` 时，额外再跑一次预测——**同一个问题、同一份证据**，
但把 world / simulation / 审查意见完整交给模型。结果单独存在 `record.shadow_forecast`，
**不参与评分、不影响 run 状态、失败也不报错**。它提供的是一次成对对照，用于回答
"如果让最终判断使用世界建模和推演，会不会更准"，而无需改动审查策略。
命名取自金融里的"影子账户"：并行记一笔账，不影响真实仓位。

**为什么它默认关闭**：每例多一次模型调用；且 `test_backtest.py` 有一条断言要求
产品路径的 forecast 调用恰好一次。需要时用 `FORECASTLAB_SHADOW=1` 开启。
