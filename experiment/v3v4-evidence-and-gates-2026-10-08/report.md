# 完整实验报告：训练数据截止之后的评测（证据质量 · 影子全依据 · 审查闸门 · 解码温度）

**日期** 2026-10-08　**套件** `forecastlab-v3v4`（20 案例：10 正 + 10 负）
**模型** `deepseek-flash`（DeepSeek-V4.1-Flash）　**数据** `results/*.json`
**轮次** v3 基线 1 轮 + v4 对照 4 轮（A/B/C/D）+ v5 当前代码 1 轮，共 6 轮 × 20 案例

---

## 1. 目的

### 1.1 背景

ForecastLab 是一条"证据优先"的二元事件预测流水线，一次运行分六个阶段：
规范化问题与检索词 → 整理证据并产出带逐字引用的发现 → 构建世界状态（主体、假设） →
主体行动推演两轮 → 审查（找漏洞并决定概率依据） → 报告（给出是/否主观概率）。

评测方式是准备一批**结果已经确定**的二元问题，让系统站在每个问题的**信息截止日**（`as_of`）
"只看当天及之前的资料"给出概率，再与真实结果比对，用 Brier 与覆盖率衡量。
评测臂有三个：`full`（完整六阶段）、`single_agent`（问题 + 同一份证据，一次调用）、
`no_evidence`（只给问题，不给证据）。

本项目所用模型（`deepseek-flash` / DeepSeek-V4.1-Flash）训练数据截止约 2025-05。
若评测题的结果发生在截止之前，模型可能"背出"答案，"给证据"与"不给证据"就没有区别；
因此本实验沿用的 20 个案例全部满足 `as_of ≥ 2025-07-01`，事件确实落在模型知识之外。

### 1.2 四个待研究的问题

本实验在同一批 20 个案例上回答四个问题。每条给出：现象 → 假设 → 检验方式 → 实测结果（细节见 §3）。

**问题 1 · 证据做厚能否提升预测质量？**
现象：v2 的证据包平均只有 2–3 条来源，且多为媒体标题级摘要，审查频繁抱怨"只有标题""缺少某类资料"。
假设：来源更多、更权威、并补入截至日状态证据后应当更准。
检验：固定温度下，同一批题目分别用薄包（46 条）与厚包（67 条）跑 `single_agent`，并以不读证据的
`no_evidence` 臂作噪声下限对照。
结果：**厚包没有更好，反而略差**（0.1217 vs 0.1130），对照组仅漂移 0.002。

**问题 2 · 让最终概率使用"世界建模 + 主体推演"，会比"仅证据"更准吗？**
背景：第 ⑤ 步（审查）决定第 ⑥ 步的概率依据；判为 `evidence_only` 时报告拿不到 world/simulation，
被要求忽略建模与推演，只有判为 `full` 才允许引用——若永远走 `evidence_only`，第 ③④ 阶段等于白算。
假设：完整建模与推演能提供"仅看证据"得不到的信息。
检验：影子预测——同一 run 内并联一次全依据预测（同一问题、同一证据），只记录不评分（见 §2.5）。
结果：**两者持平**（0.1143 vs 0.1181）；在闸门打开、15/20 案例真正以全依据出概率后仍持平
（0.148 vs 0.122），说明并非"通道没打开所以看不出"。

**问题 3 · 为什么几乎从不走全依据？闸门能否合理放开？**
现象：v2 的 20 例中 **0 例**以 `full` 依据出概率（`evidence_only` 15 例、弃权 5 例）。
假设：审查规则"`unsupported_claims` 非空即判 blocked"过于激进，挡死了全依据通道。
检验：A（原样）/ C（只放宽该条）/ B（再移除 `world.summary` 的 future_gap 检测与复审触发）三轮对照。
结果：**假设错误**——C 与 A 分布完全相同；真正的闸门是 `future_gap` → `evidence_only`。
打开它可将全依据概率从 0 提到 15 例，但精度不变；且该兜底行为有测试断言，属有意设计（见 §4）。

**问题 4 · 运行方差有多大，是否会掩盖上述结论？**
现象：同一问题、同一证据、同一代码，两次运行 `no_evidence` 对 `PN3` 给出 0.90 与 0.05。
假设：这是服务端默认采样温度造成的随机性，不是缺陷。
检验：固定 `temperature=0` 做小样重复、横向对比各轮同一臂，最后移除该参数再跑一轮（v5）。
结果：固定温度把个案漂移从 ±0.48 压到 ±0.03，但**未消除**；`no_evidence` 在各轮间浮动 0.133–0.207。
**由此确立"小于约 0.04 的差异不可解读"这条纪律，问题 1 的"改善"正是因此被推翻。**

## 2. 方法

### 2.1 套件与证据

- 20 个案例（10 正 + 10 负），全部 `as_of ≥ 2025-07-01`，结果在 2026-10-01 前已实际确定；
  模型训练数据截止约 2025-05，故不含答案泄漏。
- **加厚证据包**：证据条目 46 → 67，多数案例由 2–3 条增至 4 条；优先补入官方/一手来源
  （Apple Newsroom、FOMC 声明、NASA 公告、拜仁官方赛报、NBA 官方赛程、Xinhua 通稿等），
  并加入信息截至日当天可查的状态证据。每条证据的 `published_at` 均 ≤ 该案例 `as_of`（离线校验通过）。

### 2.2 三个评分臂

| 臂 | 说明 |
| --- | --- |
| `full` | 六阶段流水线（问题 → 证据 → 世界状态 → 主体推演 → 审查 → 报告） |
| `single_agent` | 一次调用：问题 + 同一份证据包 → 概率 |
| `no_evidence` | 一次调用：只有问题，不使用任何证据（对照） |

### 2.3 四项实验改动

| 代号 | 内容 | 归属轮次 |
| --- | --- | --- |
| 加厚 | 证据包 46 → 67 条 | v3 |
| 影子 | `evidence_only` 分支并联一次全依据预测，写入 `shadow_forecast`（`FORECASTLAB_SHADOW=1`，默认关） | v3 |
| 温度 | 请求固定 `temperature=0` | v4-A 起；**后按要求移除**（见 §5） |
| 闸门 | ②`unsupported_claims` 不再自动 blocked；①移除 `world.summary` 的 future_gap 检测；③`future_gap` 不再单独触发复审 | v4-B（①③后回退） |

### 2.4 对照设计

- **A / C 对比**：分离 ② 的单独效果（同一套件、同一温度）。
- **B 轮**：把 ①③ 一并拿掉，验证"闸门打开后全依据会怎样"。
- **D 轮**：固定温度下改用 v2 的**薄**证据包，仅跑 `single_agent` / `no_evidence`，把"证据加厚"的效果从采样噪声中分离出来。

### 2.5 什么是"影子预测"

"影子预测"是本实验加入的一段**只观测、不影响结果**的并联计算。

流水线在第 ⑤ 步（审查）判定概率依据。若判为 `evidence_only`，第 ⑥ 步（报告）拿到的输入里
**世界状态与主体推演会被清空**，并被明确要求"忽略世界建模与推演"。此时额外再发起一次预测调用：
**同一个问题、同一份证据**，但把 world / simulation / 审查意见完整交给它，并允许它引用假设与推演编号。
结果单独存进 `record.shadow_forecast`，**不参与评分、不影响 run 状态、失败也不报错**。

它的作用是提供一次**成对对照**：在同一批输入上同时得到"仅证据"与"含建模"两个概率，
从而回答"如果让最终判断使用世界建模和推演，会不会更准"，而无需改动审查策略。

命名取自金融里的"影子账户"——并行记一笔账，不影响真实仓位。该功能默认关闭，
用 `FORECASTLAB_SHADOW=1` 开启：它会让每例多一次模型调用，而
`backend/tests/test_backtest.py` 有一条断言要求产品路径的 forecast 调用恰好一次。

## 4. 结论

1. **证据加厚没有可测收益。** 固定温度下的干净对照显示厚包略差（0.1217 vs 0.1130），
   而对照组仅漂移 0.002。v3 曾观察到的 0.162 → 0.124"改善"确认为采样噪声。
   加厚唯一确凿的作用是修掉了 `PN6` 的证据冲突（三条来源对"谁淘汰皇家马德里"说法不一致，
   补入拜仁官方赛报后统一），属数据质量修正。
2. **全依据不比仅证据更准。** 两条独立证据：影子成对比较（10 例：0.1181 vs 0.1143，胜负 5:4）；
   以及闸门真正打开后（15/20 走全依据）full 0.148 vs single 0.122 仍持平。
   这次不是"通道没打开所以看不出"。
3. **闸门是设计契约，不是缺陷。** 真正的闸门是 `future_gap` → `evidence_only`；
   `unsupported_claims`（②）毫无影响；移除 ①③ 虽能让全依据通道从 0 开到 15 例，
   但 `backend/tests/test_backtest.py` 有两个用例直接断言该兜底行为
   （文档串：*A missing future close must not contaminate an approved evidence-only estimate*），
   因此按设计保留，未当 bug 修改。
4. **方差主导。** `temperature=0` 明显改善（3 例抽样中 5/6 完全一致）但未消除（该参数后已移除，见 §5）：
`no_evidence` 臂输入完全相同，各轮之间 Brier 在 0.133–0.207 间浮动；
   个案 `PN3` 在 0.90 与 0.05 之间跳变。**任何小于约 0.04 的差异都不可解读**——
   这正是结论 1 得以推翻的依据。
5. **模型对截止之后的事件确实缺少知识，但套件偏宽松**：`no_evidence` 在部分案例上得分很好
   （如 `PT1` 0.97、`PT3` 0.97），因为这些事件可由截止前的公开日程推断；
   而在无日程可依的题目上明显失手（`PN3` 曾给 0.90 且判错）。

## 5. 关于 `temperature`（解码温度）

`temperature` 是模型采样时的**随机性强度**参数，作用在每步输出词的概率分布上：

- `temperature = 0`：退化为**贪心解码**，每步都取概率最高的词，输出最确定；
- `temperature` 越大（通常 0.7–1.0）：分布被拉平，采样更随机、输出更多样。

本项目原先**没有显式传这个参数**，于是使用服务端默认值（DeepSeek 非 thinking 模式下通常为 1.0）。
后果在本实验里非常直观：同一个问题、同一份代码、同一份证据，两次运行
`no_evidence` 对 `PN3` 分别给出 **0.90** 与 **0.05**，对 `PW1` 给出 0.14 与 0.35。
这不是代码 bug，而是采样随机性。

为了压住这个漂移，v4 的 A/B/C/D 四轮曾在 `backend/app/llm.py` 里固定 `temperature=0`
（它必须与"对 `deepseek*` 关闭 thinking"配合才有意义——thinking 模式会忽略该参数）。
效果：小幅抽样 3 例中 5/6 完全一致；个案漂移从 ±0.48 量级降到 ±0.03 量级。

**该改动后来被移除**，原因有二：一是它属于实验期的对照手段，不是产品行为；
二是它并不能真正保证可复现——服务端仍会引入差异（见下）。移除后，
`temperature` 恢复为服务端默认值，A/B/C/D 四轮的数字因此对应一个与当前代码相差这一行的状态。

需要注意两点：

- **它降低但不消除方差**。服务端可能在不同副本上执行、批次拼接不同，仍会产生差异；
  本轮 `no_evidence` 臂在 A/B/C 三轮间仍从 0.185 变到 0.135。
- **它不改变能力，只改变可复现性**。固定温度不会让预测更准，其价值在于让 A/B 对比可信。

因此，**结论 1（证据加厚无效）与结论 2（全依据无增益）不依赖该参数是否存在**：
前者是同一温度下的成对对照，后者在 v3（默认温度）与 v4-B（固定温度）两种设置下都得到同样结果。
真正需要它的是"分辨小差异"的场景，而那类场景的替代方案是重复运行取平均。

## 6. 环节诊断：问题出在哪一步

| 阶段 | 产出 | 是否进入最终概率 |
| --- | --- | --- |
| ① question | 检索词 | — |
| ② evidence | 证据与发现 | 是（仅证据路径只用它） |
| ③ world | 主体、假设 | **否** |
| ④ simulation | 行动、状态推演 | **否** |
| ⑤ review | 审查意见 + 决定概率依据 | 决定走向 |
| ⑥ forecast | 概率 | 输出 |

在 v4-A/C（现行策略）下，③④ 的产出不进入最终概率；这不是实现缺陷，而是第 ⑤ 步
"发现缺口即降级为仅证据概率"这条策略的直接结果。v4-B 证明：即便把它打开、让 15/20
走全依据，精度也不变（见结论 2），因此**继续调整第 ⑤ 步不会带来分数收益**。

## 7. 局限

- **单轮运行**。v4 四轮虽固定了温度，残余方差仍足以翻转小于 0.04 的差异；本报告所有结论都受此限制。
- **样本量 20**，分类层面每类仅 4–7 例，分层数字只能作方向性参考。
- 套件中多例可由截止前公开日程推断，对 `no_evidence` 臂偏宽松，削弱了它作为"强对照"的作用。
- 影子预测只在 `evidence_only` 分支触发，故全依据门与弃权案例没有影子值，成对样本仅 10 例。
- 影子预测复用同一份 world/simulation 产出，检验的是"最终判断是否使用建模"，而非"建模本身的质量"。
- B 轮同时改动 ①②③，未分别归因；由 A 与 C 完全相同可知主要效果来自 ①③。
